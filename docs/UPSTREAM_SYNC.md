# MOA → MOA Lite 동기화

검토 기준: 원본 `sidetool/moa`의 `f31084a21bb16cbbf165a31e43d1a2f397105994` (2026-10-13).

## 확장 소스 호환성

- `packages/extensions`의 bootstrap, 필터, preference, 저장소 파서, 타입과 vendor 호스트 계약은 원본과 같습니다. HTTP 옵션·runtime 계약도 같은 기준으로 맞췄습니다.
- `source-identity.ts`는 원본 구현입니다. 설치 메타데이터로 확인한 도메인 변경, 번호 도메인 관찰, 상세 응답의 작품별 별칭, opaque ID/상대 주소 구분, 롤백에서 ID를 보존합니다.
- `Sources`의 작품 저장·상세 조회·영상 추출·탐색 세대 검증을 이식했습니다. 소스가 바뀌는 동안 끝난 옛 요청 결과를 버리고, 새 주소 실패 시 기존 주소를 시도합니다. 추측으로 임의 도메인을 탐색하지 않습니다.
- HLS data URL 검증은 원본과 같은 크기·URI·암호화 제한입니다. 디코더만 Node Buffer 대신 표준 Uint8Array를 사용합니다. 서버 중계 대신 브라우저 Blob과 직접 영상 요청으로 재생하며, Cookie/Authorization은 확장이 명시한 유효한 `originalUrl`의 호스트에만 적용합니다.
- JS는 기존 브라우저 QuickJS 워커에서 실행합니다. HTTP에는 기존 크기·시간·요청 수 제한을 유지합니다. `browserSession`/WebView 요청은 `source_browser_unavailable`로 명시적으로 거절합니다. 브라우저 인증 기능을 새로 제공하지 않습니다.
- APK, 분리 오디오/영상·여러 구간 EDL, HTTP 영상 등 기존 라이트 비지원 형식은 그대로 제한됩니다. 원본과 같은 확장 계약을 사용한다는 것이 서버 전용 재생 기능까지 지원한다는 뜻은 아닙니다.

## 반영한 사용자 기능

- 그룹으로 묶인 이어보기 카드도 가장 최근에 시청한 소스의 실제 회차·위치로 재생합니다. 완료된 다른 소스의 옛 진행 상황을 되살리지 않습니다.
- 홈의 이어보기/내 목록 범위를 탐색 소스 범위와 분리합니다. 원제·대체 제목·확정 TMDB 연결을 이용한 로컬 검색을 반영했습니다. 검색 실패마다 외부 TMDB를 추가 조회하는 경로는 넣지 않았습니다.
- AniSkip은 현재 재생 세션의 실제 영상 길이를 사용합니다. 길이가 정정되거나 오프닝/엔딩 일부만 반환돼도 이미 받은 구간을 유지합니다. 다른 스트림의 구간은 재사용하지 않습니다.
- 원본의 설정 카테고리 화면, 소스 필터/선택 UI, 자막 슬라이더·수치 입력·미리보기와 ASS/VTT 표시 개선을 사용합니다. 라이트에서 제공하는 기능만 메뉴에 표시합니다.
- 자막 모양은 이 기기·계정·프로필별, 싱크는 회차별로 저장합니다. 기존 기기 설정은 최초 프로필로 한 번 이관합니다. 모양 설정에 서버 API나 Redis 쓰기를 추가하지 않습니다.
- 번역 권한/키/잔액 오류를 구분하고 영구 오류의 반복 요청을 줄입니다. 할당량 오류에는 대기시간을 늘리고, 취소 시 대기 중인 재시도도 중단합니다. 제공자·키 저장 방식은 기존 라이트 구조입니다.

## 라이트에서 유지하는 구현

로컬 자막 가져오기, 한국어 ZIP/7z/RAR 해제, 검색 캐시와 64회·20초 검색 예산, 자막이 보이는 PiP, 회차별 자막 선택 기억, 재생 종료 직전 진도 저장, 다른 소스로 전환할 때 자막·싱크 전달은 유지합니다. 원본의 서버 자막 업로드/디스크 저장으로 교체하지 않습니다.

주소 별칭은 시청·내 목록에 필요한 자료만 기존 동기화 문서에 함께 저장합니다. 내부 임의 site ID는 기기마다 달라도 전송 값은 동일하게 정규화합니다. 기존 DB/동기화 행은 삭제하거나 초기화하지 않습니다.

## 이번 범위에서 제외한 기능

서버 브라우저 인증, 영상 중계·다운로드·트랜스코딩, 전체 소스 목록 선조회, 쇼츠/트레일러 선로딩, 서버 자막 라이브러리, 자동 싱크 분석과 큰 일본어 폰트는 제외했습니다. 추천/일반 영화 구간 서비스도 추가 외부 조회와 동기화 설계를 별도로 검토할 대상으로 남깁니다.

## 검증과 후속 업데이트

원본의 주소/ID 회귀 테스트와 라이트 SQL.js 동기화 테스트를 함께 사용합니다. 인라인 HLS는 실제 QuickJS 추출 → 라이트 스트림 선택 → Blob 생성 및 설치된 연결 확장의 규칙 등록을 검증하고, 암호화 영상의 브라우저 재생·탐색도 검사합니다.

스타일 기준 커밋과 파일 지문은 `apps/lite/test/upstream-ui.json`에 기록합니다. 원본에서 다시 이식할 때는 브라우저 재생/모바일 설정/기기 동기화 테스트와 `verify:vercel`을 함께 실행해야 합니다. 원본 전체 디렉터리를 덮어쓰면 라이트의 브라우저 저장·네트워크 처리와 Vercel 제한을 잃을 수 있습니다.
