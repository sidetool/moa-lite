## P1·P2 회귀 수정 검증

2026-10-05 추가 검토에서 확인한 7개 문제를 수정했습니다. 기본 사용 경로는 **연결 확장 없는 Vercel 조회 중계 + 원본 영상 직접 재생**이며, 아래 카탈로그·재생 검사는 연결 확장을 설치하지 않은 Chromium에서 실행했습니다.

- 요청 시작 시 프로필을 고정합니다. 잠금 대기 중 다른 프로필로 전환해도 설정은 요청한 프로필에만 저장됩니다. 번역 배치도 시작한 프로필을 유지합니다.
- Worker는 같은 DB 스냅샷을 계속 사용하며, 응답 이후 완료된 캐시·메타데이터 변경을 별도 체크포인트로 저장합니다. 다른 탭이 먼저 저장한 경우 변경 전 행과 비교하여 캐시 변경만 병합하며 사용자 설정·기록 및 새 소스 설정을 덮어쓰지 않습니다. 목록 갱신 후 다음 조회와 새로고침에서도 새 목록이 유지되는 것을 확인했습니다.
- 원본의 인라인 SRT/VTT/ASS 처리와 영상 MIME 판정을 공통 코드로 재사용합니다. 자막 Blob 내용과 확장자가 없는 HLS의 실제 플레이어 재생·세그먼트 요청을 확인했습니다.
- 이미지 헤더는 계정에 묶인 암호화 티켓으로 전달합니다. 필수 User-Agent를 요구하는 이미지가 정상 응답하고 헤더 원문이 이미지 URL에 노출되지 않는 경로를 검증했습니다.
- Vercel 조회 중계와 선택적 연결 확장은 PUT/PATCH/DELETE/OPTIONS, 리다이렉트 옵션·상태와 응답 헤더를 보존합니다. 실제 HTTP 서버를 사용한 전송 검사에서 본문과 헤더를 확인했습니다. 이 과정에서 DELETE/OPTIONS 본문의 Node HTTP Content-Length 처리도 보완했습니다.
- 로그아웃 전파는 서버 로그아웃 성공 이후에 수행해, 다른 탭이 인증 상태를 다시 복구하는 경합을 방지합니다.

선택적 연결 확장도 Chromium에 실제로 설치하고 로컬 HTTPS 서버로 검증했습니다. 자동/수동 리다이렉트, Location·사용자 정의 헤더·Set-Cookie, PUT/PATCH/DELETE 본문·User-Agent, 리다이렉트 대상 권한 거부 및 로그인된 소스 탭을 확인했습니다. 응답 헤더 관찰은 [Chrome webRequest 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/webRequest)의 권한·extraHeaders 규칙을 따릅니다. 실제 외부 사이트의 접근 허용 여부를 검증한 것은 아닙니다.

`test:browser`는 기존 통합 검사에 `test/regressions.ts`와 `test/connector-browser.ts`를 추가로 실행합니다. 결과 로그는 `.state/review/fix-{all-tests,typecheck,build,browser,regressions,connector-browser,vercel}.log`에 있습니다. 기존 CPU 제한 검사에서 한 차례 외부 5초 대기 시간이 초과됐으며, 단독 재실행에서는 CPU·메모리 제한을 포함한 전체 통합 검사가 통과했습니다.
